AjraVerify — what changes in the answer pipeline

Left: today (no gate). Right: with the AjraVerify module. The farmer-facing steps stay the same — a deterministic safety gate is inserted before delivery.
Shared steps: question intake (WhatsApp / IVR / web) → Golden Dataset → Package of Practices → AI fallback drafts an answer
✕ BEFORE — today
AI fallback drafts the answer — an LLM writes the reply, including any dosage, interval and chemical names unchecked text
▼
⚠ No automated safety check. Nothing verifies the dosage claims against trusted agricultural data — not the chemical module, not PoP, not the Golden Dataset.
▼
Answer is delivered to the farmer immediately before any human reads it
▼
Question + AI answer are copied to the Review System — a human expert may notice a problem later, after delivery post-hoc, human-only
An unsafe dosage recommendation can reach a farmer before anyone sees it. The only quality gate is one expert reading it unaided, within SLA.
✓ AFTER — with AjraVerify
AI fallback drafts the answer — same generation step as today
▼
🛡 AjraVerify gate (runs before delivery)
  • Extract claims — chemical names, dosages (ml/L, g/acre), intervals ("every 5 days"), spray counts
  • Resolve each claim against trusted data — chemical catalogue, PoP DB, Golden Dataset
  • Decide with a deterministic policy engine (no LLM in the decision)
  • Persist a receipt — every claim, match result, verdict and reason, for audit
VERIFIED CONDITIONAL REVIEW_REQUIRED BLOCKED
▼
Delivery depends on the verdict: verified → ships · conditional → ships with a caveat · review required / blocked → routed into the existing expert queue instead of silent delivery
▼
Experts open the queue with per-claim evidence — matched sources and mismatches shown next to the answer, not a bare text box
No AI answer ships with unchecked dosage or interval claims. Unsafe or unverifiable advice escalates to humans with evidence — and every gate decision is auditable.
Where it lives: new TypeScript module inside the existing backend — no new service
Facts come from data: chemical module · PoP · Golden Dataset — never hardcoded in code
Milestone 1: zero LLM calls, fully offline-testable · Milestone 2: LLM extracts, policy still decides
